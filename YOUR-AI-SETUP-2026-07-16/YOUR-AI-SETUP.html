What is helping

These parts protect the work or give the AI useful context. The audit recommends keeping them.

Claude Code permissions + backup hooks (.claude/settings.json)

Claude Code can run a fixed allowlist of commands without asking, and a hook auto-pushes to origin after every commit plus warns at session end if anything is unpushed.

Why it stays: This is the actual enforcement mechanism behind CLAUDE.md's 'origin/main is a backup' protocol — a real hook, not just written guidance. It turns a stated rule into a working check, which is the desired pattern.

Standing project instructions (CLAUDE.md)

This file is auto-loaded at the start of every session in this project and sets the dual-write memory protocol, the migration safety checkpoint, the origin-backup protocol, and the architectural invariants.

Why it stays: Well-structured standing instructions: each protocol states its origin/rationale, points to a supporting memory file, and the six architectural invariants are stated as settled decisions with 'don't relitigate' guidance. This is exactly the shape a project CLAUDE.md should have.

Entity extraction tool definition (lib/agents/entity/tool.ts)

Defines the 'extract_entities' Anthropic tool (name, description, default persist=false) that the Orchestrator calls inline to resolve named entities against the user's graph.

Why it stays: This is a real, in-use tool definition shared between the synchronous Orchestrator path and the async entity-agent listener ('dual-mode pattern: one core, two callers', per its own comment) — a clean single-source-of-truth pattern, not duplicated logic.

Tagger tool definition (lib/agents/tagger/tool.ts)

Defines the tagging tool used inline by the Orchestrator and shared with the async tagger-agent listener.

Why it stays: Same shared-core dual-mode pattern as the entity tool: one definition, two callers (inline orchestrator + async listener), which is the correct way to give a control one job and one home.

Capture Agent listener (lib/inngest/agents/capture-agent.ts)

Listens for memory/ingested, logs the event, and serves as the documented fan-out point for the Tagger and Entity agents.

Why it stays: Small, single-purpose, and its own comment correctly documents both its current behavior and a noted future change (moving the INSERT here under a restricted DB role in multi-tenant production) — a good example of intent being stated rather than assumed.

Entity Agent listener (lib/inngest/agents/entity-agent.ts)

Async listener that loads a memory, respects the orchestrator's skip_async_fanout flag, and persists resolved entities via the shared entity core.

Why it stays: Correctly implements the documented dedupe gate so draft memories aren't double-processed before the user accepts them — the skip flag and the Orchestrator's inline preview are consistent with each other.

Globe Extraction Agent listener (lib/inngest/agents/globe-extraction-agent.ts)

Listens for globe/pin.saved, runs modal-text extraction, then resolves newly extracted people/org stubs against the graph, async so pin save never blocks on Claude.

Why it stays: Its own comment documents the idempotency property (re-extraction only surfaces new names) and the async-by-design rationale, matching the async pattern used by the other agents.

Tagger Agent listener (lib/inngest/agents/tagger-agent.ts)

Mirrors entity-agent's structure: loads the memory, respects skip_async_fanout, classifies via the shared tagger core, and flags sensitive content.

Why it stays: Same correct dedupe-gate pattern as entity-agent, applied consistently.
